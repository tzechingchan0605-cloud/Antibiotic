# VL4 專用 Google 雲端設定 / Dedicated VL4 Google cloud setup

**目前狀態 / Current status:** `cloud-config.js` 的 `CLOUD_ENDPOINT` 為空字串。VL4 的完整答案及圖片會先保存本機，待傳佇列仍會保留；尚未連接任何正式 Google 收集端。自動測試只使用隔離服務替身，沒有傳送測試學生資料至 Google，也不代表 Google 已部署成功。

`CLOUD_ENDPOINT` is intentionally empty. Complete answers and images are backed up locally and queued, but no live Google collection service is connected. Automated tests use isolated mocks only; they do not demonstrate an actual Google deployment.

## 繁體中文設定步驟

1. 使用你自己的 Google 帳戶建立一份**新的 VL4 Google 試算表**及**新的獨立 Apps Script 專案**。不要沿用 VL2 試算表、正式 `/exec` 網址或學生資料。試算表不需公開共用。
2. 將 `google-apps-script/Code.gs` 的內容放入該專案的 `Code.gs`。新增名為 **Bridge** 的 HTML 檔案，貼上 `google-apps-script/Bridge.html` 的內容。
3. 開啟 Apps Script 的「專案設定」→「指令碼屬性」，新增以下私人屬性。**不要在聊天、前端、Git 或試算表儲存教師密碼。**

   | 屬性 | 內容 |
   | --- | --- |
   | `SPREADSHEET_ID` | 新試算表網址 `/d/` 和 `/edit` 之間的 ID。 |
   | `SETUP_TEACHER_PASSWORD` | 密碼管理器產生的隨機長密碼，建議至少 24 個字元；程式最低接受 20 個字元。 |
   | `ALLOWED_APP_ORIGINS` | VL4 網站的完整來源，例如 `https://yourname.github.io`。多個來源以逗號分隔，不含路徑、結尾斜線或萬用字元。開發時可另加 `http://localhost:4173`（應與實際伺服器埠號一致）。 |

4. 在 Apps Script 編輯器選取 **`initializeVL4_`** 並執行。首次執行時，使用擁有者帳戶授權試算表存取。此函數使用 `SpreadsheetApp.openById()`，不使用 `SpreadsheetApp.getUi()`。尾端 `_` 令初始化函數無法經 `google.script.run` 公開呼叫。
5. 初始化完成後，確認試算表出現 `VL4_Records` 及 `VL4_PayloadChunks`。私人屬性會新增 `TEACHER_PASSWORD_SALT`、`TEACHER_PASSWORD_HASH` 和 `CURSOR_SECRET`，並刪除明文 `SETUP_TEACHER_PASSWORD`。保留其餘屬性。請自行保存原始教師密碼，日後在教師儀表板輸入。
6. 選擇「部署」→「新增部署」→ 類型「網頁應用程式」。**執行身分選「我」（擁有者）；誰可以存取選「任何人」**。部署並完成 Google 授權，複製以 **`/exec`** 結尾的網址。不是 `/dev`、試算表網址或編輯器網址。部分學校 Workspace 管理政策不容許「任何人」；這種情況需由管理員允許，或使用可公開部署的自有帳戶。
7. 將該 **VL4 新網址**填入 `cloud-config.js` 的 `CLOUD_ENDPOINT`。前端沒有教師密碼。網站必須以 HTTP(S) 伺服器開啟，不能直接使用 `file://`。請直接開啟 VL4 網站；嵌在另一網站的 iframe 中運行尚未驗證。
8. 更新程式碼後，使用「部署」→「管理部署」→ 編輯現有部署 →「新版本」→「部署」。保留同一部署網址；只儲存編輯器內容不會更新已發布版本。若建立了新部署，需更新前端網址，並重新部署前端網站。

教師密碼重設：在私人指令碼屬性加入新的 `SETUP_TEACHER_PASSWORD`，由擁有者從編輯器再次執行 `initializeVL4_`。新密碼會取代舊雜湊，明文屬性再次被刪除。不要刪除 `SPREADSHEET_ID` 或公開屬性值。

## English setup steps

1. With your own Google account, create a **new VL4 Google spreadsheet** and a **new standalone Apps Script project**. Keep the spreadsheet private. Do not reuse the VL2 spreadsheet, production `/exec` URL or student data.
2. Copy `google-apps-script/Code.gs` into the project's `Code.gs`. Add an HTML file named **Bridge** and copy `google-apps-script/Bridge.html` into it.
3. Open Apps Script **Project Settings → Script Properties** and add the private properties below. Never place the teacher password in chat, frontend code, Git or a spreadsheet.

   | Property | Value |
   | --- | --- |
   | `SPREADSHEET_ID` | The new spreadsheet ID between `/d/` and `/edit` in its URL. |
   | `SETUP_TEACHER_PASSWORD` | A random password generated by a password manager: at least 24 characters recommended; the code requires at least 20. |
   | `ALLOWED_APP_ORIGINS` | Exact VL4 website origins, comma-separated. Example: `https://yourname.github.io`. No path, trailing slash or wildcard. For development optionally add `http://localhost:4173`, using your actual server port. |

4. In the script editor, select and run **`initializeVL4_`**. Authorize spreadsheet access as the project owner. Initialization uses `SpreadsheetApp.openById()` and does not need a spreadsheet UI. The trailing underscore prevents public invocation through `google.script.run`.
5. Verify that the spreadsheet now has **`VL4_Records`** and **`VL4_PayloadChunks`**. Initialization creates private `TEACHER_PASSWORD_SALT`, `TEACHER_PASSWORD_HASH` and `CURSOR_SECRET` properties and deletes the plaintext setup password. Keep these properties. Retain the original teacher password privately for entering into the dashboard.
6. Choose **Deploy → New deployment → Web app**. Set **Execute as: Me (the owner)** and **Who has access: Anyone**. Authorize and deploy, then copy the URL ending in **`/exec`**. Do not use `/dev`, a spreadsheet URL or the script editor URL. School Workspace policies may prohibit anonymous web apps; the administrator must permit this, or the owner must use an account that allows it.
7. Set the **new VL4 URL** as `CLOUD_ENDPOINT` in `cloud-config.js`. The frontend never contains the teacher password. Serve the website over HTTP(S); `file://` is unsupported. Open VL4 directly in the browser; running the whole application inside another website's iframe has not been validated.
8. To publish later backend changes, choose **Deploy → Manage deployments → Edit → New version → Deploy**. Keep the existing deployment URL. Saving files in the editor alone does not update the deployed version. A newly created deployment requires updating the frontend endpoint and republishing the frontend website.

To reset the password, set a new private `SETUP_TEACHER_PASSWORD` property and run `initializeVL4_` from the owner's script editor. This replaces the hash and removes the new plaintext property. Keep `SPREADSHEET_ID` and other private properties intact.

## 運作及安全範圍 / Behavior and security scope

- **獨立命名空間 / Isolation:** 模組為 `VL_BIO_ANTIBIOTICS`；本機佇列、完整備份和確認鍵均以 `vl4.antibiotics.cloud.` 開頭。工作表獨立命名為 `VL4_Records` 和 `VL4_PayloadChunks`。切換帳戶不能刪除舊探究或待傳佇列。
- **本機優先 / Local first:** 每次 `enqueue(record)` 先序列化完整快照並寫入本機備份及待傳佇列，再開始網路請求。同一 ID 的高版本取代低版本；同版本內容不可更改。應用每次修改快照均增加 `version`。離線錯誤保留資料並以延遲重試；恢復網路及重試按鈕均可補傳。
- **真實確認 / Real acknowledgment:** `iframe load`、橋接握手、健康頁及請求發出不代表已保存。只有後端回傳 `saved:true`、正確模組、正確探究 ID 及足夠新的 `acceptedVersion` 才清除該佇列項目。確認同時與使用的 VL4 網址綁定；空佇列但沒有保存確認不會宣稱已同步。狀態只描述本機待傳資料。
- **完整圖片 / Complete images:** 完整 JSON 拆成最多 40,000 字元的片段，以固定 `json:` 文字前綴保存，避免單一儲存格超過限制及學生文字變成公式。清單讀取時依順序重組，再驗證 SHA-256。保存先寫入片段，再更新該探究的唯一索引列，最後執行 `SpreadsheetApp.flush()` 才確認。重試不新增第二份探究；亂序舊版本不覆蓋新版本。試算表配額、Apps Script 執行時間、瀏覽器儲存配額和可用容量仍適用。
- **教師存取 / Teacher access:** 指定教師電郵只控制介面路由，不能讀取資料。每一頁清單都驗證密碼，游標經 HMAC 簽署及限時有效；前端取得全部頁及正確總筆數後才回傳完整陣列。任何頁失敗均拒絕整次讀取，不以部分資料代替全班紀錄。清單以首頁開始時的筆數為快照邊界；讀取期間新加入的探究會於下次重新整理出現。
- **密碼 / Password:** 密碼只在目前頁面的輸入及傳輸中使用，不寫入本機、答案、操作事件、Excel 或日誌。後端保存隨機鹽值與 SHA-256 雜湊，採恒定迴圈比較。SHA-256 並非慢速密碼衍生函數，故須使用高熵隨機長密碼；此服務不是學校身分認證或通用帳戶系統。
- **來源驗證 / Message validation:** 後端橋接頁只服務 `ALLOWED_APP_ORIGINS` 中的完整來源。兩端檢查來源、來源視窗、模組、隨機通道及請求識別碼；前端驗證 Google 來源及自己 iframe 的子視窗後，固定該來源及視窗。後续傳訊不使用 `'*'`。Google HtmlService 的內層沙盒 iframe 能透過此方式連線，但正式 Google 網頁仍需實際瀏覽器驗證。
- **示範排除 / Demonstration exclusion:** 前端和後端均拒絕 `demo:true`、非 VL4 模組、教師角色及教師電郵的學生保存請求。教師示範不應傳入 `enqueue`。學生寫入端是匿名教學收集端：姓名、班別和電郵是學生自報，不能證明其身分。請保護部署網址及按學校政策管理資料。
- **維護 / Maintenance:** 每次新版保存會留下不再使用的舊片段；它們不是額外的探究紀錄。擁有者可在備份後從編輯器執行私人 **`pruneOrphanChunks_`** 清理孤立片段。不要手動修改資料索引或片段；格式或校驗失敗會阻止清單讀取。

## 隔離測試與正式驗證 / Isolated tests and live validation

Run `node --test tests/cloud-sync.test.mjs`. These tests cover local-first persistence, immutable snapshots, offline preservation, retry, acknowledgment validation, concurrent newer edits, teacher/demo exclusion, full paging, authentication failure, origin/window/channel/request-ID checks, server idempotency, stale requests, large images, chunk checksums and secret initialization. All transports and Google APIs are mocked. No live endpoint is contacted.

正式驗證尚未完成。取得新的 VL4 `/exec` 後，先建立一個**另外的測試試算表和部署**，用非學生的測試資料驗證以下情況；正式收集端不要接收自動測試資料。

Live validation remains outstanding. After obtaining a new VL4 `/exec`, use a **separate staging spreadsheet and deployment** with non-student test records. Do not send automated test fixtures to a production collection service.

1. 在兩個獨立瀏覽器或裝置登入學生與教師；學生完成探究及圖片，確認後端保存後出現「已確認同步」，教師密碼驗證後能讀取同一完整資料。 / Use separate student and teacher browsers/devices, submit answers and an image, verify a confirmed save and the matching complete teacher record.
2. 測試離線、重新上線、重新整理和重新傳送同 ID/version；後端不應產生重複探究，較低版本不應覆蓋較高版本。 / Verify offline recovery, refresh, retry, idempotency and stale-version protection.
3. 用超過 25 筆測試紀錄驗證全頁讀取和全班 Excel；錯誤密碼或任一頁失敗須阻止全班匯出。 / Verify more than 25 staging records, complete paging, workbook export, incorrect-password rejection and blocking export after a page failure.
4. 檢查教師示範不在學生表格或 Excel，設計圖片及原始研究計劃完整，且新登入不刪除其他探究。 / Verify demo exclusion, complete designs and original plans, and preservation of other inquiries on new login.
5. 驗證網站網域已加入允許來源，瀏覽器沒有 Google Cookie、學校政策或沙盒限制所造成的連線錯誤。 / Verify allowed origins and any Google cookie, school policy or sandbox limitations in the actual browser.
